# P1: the app speaks protocol v2

Approved 7 Nov 2026. Sources: droidthumb-protocol origin/main (package 2.0.0), droidthumb-server origin/dev. Route: `POST /v1/accounts/sign-in-token` replies `{ sign_in_token, account_id }` (server `src/paid/oauth/interaction-routes.ts`).

## Changes
1. `wireprotocol/Messages.kt`: ClaimAccount becomes SignIn (`sign_in`: `account_token`, `install_hint`); Claimed becomes SignedIn (`signed_in`, `account_id`); ClaimRejected becomes SignInRejected (`sign_in_rejected`, reasons as the schema lists them, with `devices`); new SignOut (`sign_out`) and SignedOut (`signed_out`). Welcome gains `accounts: Boolean` and `account_id: String?`.
2. `services/transport/DeviceTransportClient.kt`: subprotocol `droidthumb.v2`, hello `protocolVersion` 2. `sign_in` carries `install_hint` = `Settings.Secure.ANDROID_ID`, as the schema describes. `replace_device_id` is never sent. `signOut()` sends `sign_out` and waits for `signed_out` with the same bounded wait as sign-in (5 s). Signing out always signs out locally at once, whether or not `signed_out` arrives; a persisted pending flag makes the next connection send `sign_out` first, and the flag clears only when `signed_out` arrives. Close code 4004 (`CLOSE_REPLACED`): stop reconnecting, sign out locally (no `sign_out` message needed, the server has already moved the phone), show: "This account is now used on another phone. Sign in again to use DroidThumb here." No retry loop.
3. `services/account/AccountApiClient.kt`: token path `/v1/accounts/sign-in-token`, response field `sign_in_token`.
4. `ui/viewmodels/AccountViewModel.kt`, HomeScreen, AccountSessionCard, OnboardingScreen, `strings.xml`: claim becomes sign in throughout, user-facing text included; AlreadyClaimedByOther removed. With welcome `accounts: false` the app hides sign-in and never sends `sign_in`; `sign_in_rejected` with `accounts_unsupported` shows that this server has no accounts and leaves the phone usable.
5. `wireprotocol/StepDispatcher.kt` and accessibility: `type_text` replaces the field's content by default; `append: true` appends; `clear` removed. `submit: true` performs `AccessibilityNodeInfo.AccessibilityAction.ACTION_IME_ENTER` on the focused field after typing; if the node doesn't offer that action or `performAction` returns false, the step fails with `submit_unsupported` (the text stays typed). `read_screen` reports `locked` from `KeyguardManager.isKeyguardLocked` and still returns the screen when locked (it never fails with `device_locked`). Every other step checks the lock first and fails with `device_locked` while the phone is locked.
6. AI connections: the app's existing list and revoke switch from HTTP to `list_ai_connections` / `ai_connections_list` and `revoke_ai_connection` / `ai_connection_revoked` over the phone connection, with errors `not_signed_in` and `not_found` shown plainly. Remove the HTTP calls they replace.
7. Tests: MessagesTest, DeviceTransportClientTest, StepDispatcherTest, AccountViewModelTest and others as needed; v2 fixtures copied verbatim from the protocol's `examples/v2/` into test resources, v1 fixtures deleted. Cover: sign-in, sign-out with and without a reply, pending sign-out on reconnect, 4004 stops reconnecting, accounts false, type_text replace/append/submit/submit_unsupported, locked read_screen, device_locked, AI connection list/revoke and both errors.
